07 — URL and locale scheme

Chinese is the default, 英文是镜像

Route shape

cn.cys.com.sg/zh/about/history
cn.cys.com.sg/en/about/history

Locale is the first path segment. / redirects to /zh. Route segments stay English in both locales — stable, greppable, and avoids percent-encoded Chinese URLs.

Switcher behaviour

The 中文 | ENG control swaps only the locale segment and preserves the rest of the path plus query. A visitor deep in /zh/business/institutions lands on the English equivalent, never the homepage.

SEO

Reciprocal hreflang on every page pair plus x-default → /zh. One sitemap per locale, both referenced from robots.txt. Self-canonical per locale — never canonicalise EN to CN.

Parity rule

Every deck screen exists in both languages, so full parity is the assumption: 28 routes total. If the client wants English reduced, that halves the content workload — but it needs deciding before Lofi, not after.

08 — Who owns what

Three content sources

SANITY — CLIENT EDITS

Marketing copy

Every page body, headline, card, milestone, partner story and contact detail. Bilingual fields on one document, so CN and EN never drift apart.

11 document types. Client edits without a deploy.

SUPABASE — USERS WRITE

Forum & submissions

Posts, comments, profiles, moderation events, enquiry and feedback submissions. All under row-level security; all reads server-side.

Phase 2, except the two Phase 1 forms.

CODE — WE OWN

Chrome & structure

Header, mega menu, footer, language switcher, currency ticker, routing, legal page shells.

Changing these is a deploy, so nav labels should settle at sign-off.

SANITY DOCUMENT TYPES — 11 + 1 SINGLETON

homePage · aboutPage · milestone · culturePage · corridorPage · partner · partnerStory · businessPage · individualPage · contactPage · legalPage · siteSettings

siteSettings carries nav labels, footer groups, contact details, the currency list and social links — one document, edited once, read on every page.

BILINGUAL FIELD PATTERN

Every translatable field is an object with zh and en keys on a single document — not two parallel document trees. One editor screen shows both languages side by side, so a copy change can't land in Chinese and silently miss English.

Missing translation falls back to zh and is flagged in Studio, never rendered blank.

REQUIRES A DEPLOY

Adding a route · changing a URL · adding a nav item · new page template · new component · anything in the header, footer, or language switcher chrome. This is why nav labels and the URL tree should settle at sitemap sign-off — after Lofi they cost a rebuild, not an edit.

09 — What sign-off means

Four decisions in this document

  • Header taxonomy is canonical. 伙伴故事 sits under 中新合作走廊, 星威论坛 under 企业合作. The footer follows the header, not the reverse.
  • 华商社群 becomes a label, not a page. No screen was ever designed for it. If the client wants a real landing page, that is a new route and a new Lofi.
  • Full CN/EN parity — 28 routes. Every screen ships in both languages unless the client reduces English scope now.
  • Auth ships in Phase 1, gates nothing until Phase 2. The header shows 注册 | 登录 on every deck screen; building the routes now avoids a dead link in the demo.
